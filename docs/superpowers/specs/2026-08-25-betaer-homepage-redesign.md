# betaer 项目主页轻量重构设计

## 目标

把 `https://betaer.github.io/` 重构为一个主题清晰、层级明确的静态主页。页面优先介绍 betaer 的浏览器安全工具，同时在同一主页保留完整域名资产列表和联系方式。

成功标准：

- 用户进入首屏即可理解 betaer、AI Signal Guard 与 Password Generator 的关系。
- 工具项目是页面的主内容，域名资产作为独立次级分区展示，不与项目卡片混排。
- 页面标题、描述、结构化数据和可见内容一致承认“项目 + 域名资产”两类内容。
- 保持零构建、零框架、纯静态部署，不增加不必要的交互与依赖。
- 桌面端与移动端都能快速浏览项目、域名和联系方式。

## 定位与内容层级

页面定位为“betaer 的公开项目与域名资产主页”，而不是只声明为安全工具实验室。

内容顺序固定为：

1. 顶部导航与品牌标识
2. 首屏定位与主要入口
3. 浏览器安全工具
4. 工具共同遵循的安全原则
5. 域名资产列表
6. 关于、开源与联系方式

工具区在视觉面积、标题层级和页面顺序上保持主导。域名区使用明显的分区标题和独立说明，避免用户把域名理解为安全工具产品。

## 页面结构

### 顶部导航

- 左侧显示 `betaer`。
- 右侧提供“项目”“域名”“GitHub”“联系”四个入口。
- “项目”“域名”“联系”使用页内锚点，GitHub 使用外部链接。
- 桌面端保持单行；移动端缩减为紧凑布局，不引入复杂菜单脚本。

### 首屏

- 主标题：明确说明 betaer 构建浏览器端安全工具。
- 辅助文字：补充域名资产也在本页展示，避免页面定位与后续内容冲突。
- 主按钮进入项目区，次按钮访问 GitHub；两个按钮表达不同意图。
- 视觉保持轻量、可信和技术导向，不使用大型插画、渐变光晕或复杂动画。

### 项目区

展示两个项目：

- AI Signal Guard：网络、浏览器隐私与环境一致性诊断。
- Password Generator：浏览器本地生成密码、记忆短语和 PIN。

每个项目包含项目名称、具体用途、核心安全边界、访问项目链接和源码链接。项目之间使用非对称但克制的排版，不使用模板化的三列功能卡。

### 安全原则

用简短内容说明两个工具共同遵循的原则：

- 浏览器优先
- 敏感数据本地处理
- 可公开审计
- 明确能力边界

该区只解释可验证的设计原则，不加入未经证明的安全承诺或虚构指标。

### 域名资产

- 保留现有全部域名及中文含义。
- 域名统一使用正常英文句点显示，例如 `codeis.law`，不再使用中文句号。
- 使用响应式双列列表；每项只包含域名和现有含义，不虚构价格、状态或用途。
- 联系说明统一表述为“域名咨询”，不在每个域名后重复销售文案。
- 域名文本默认不自动链接到未知站点，避免把用户导向未核验内容。

### 页尾与联系

- 说明 betaer 是两个浏览器工具的作者。
- 提供 GitHub、电子邮箱和现有 QQ 联系入口。
- 项目合作与域名咨询共用一个清晰联系区，但使用不同文案说明来意。
- 电子邮箱继续采用易读的反垃圾邮件写法，不在页面脚本中做复杂解码。

## 视觉方向

这是“轻量静态项目主页”，面向关注隐私工具、开源代码和域名资产的访问者。视觉语言采用冷静、可信、技术导向的浅色系统。

设计参数：

- `DESIGN_VARIANCE: 5`：有清楚层级和少量非对称排版，但不做实验性布局。
- `MOTION_INTENSITY: 2`：只保留悬停、焦点和按压反馈。
- `VISUAL_DENSITY: 4`：项目说明舒展，域名列表紧凑。

设计约束：

- 使用一套冷灰中性色和一个蓝色强调色。
- 使用 CSS 变量统一颜色、间距、圆角和阴影。
- 按钮使用统一圆角；项目容器使用同一圆角尺度。
- 页面不使用外部字体、图片生成资源或 JavaScript 动画。
- 保留并更新现有 OG 图片，使其同时体现项目与域名主页定位。
- 所有可交互元素提供清晰的键盘焦点状态。
- 尊重 `prefers-reduced-motion`，并保证无动画时信息完整。

## SEO、Schema 与内容一致性

### 元数据

- `<title>` 同时包含 betaer、项目与域名主页语义，并保留两个项目名称中的至少一个核心关键词。
- Description 明确介绍两个浏览器安全工具和域名资产列表。
- Canonical 保持 `https://betaer.github.io/`。
- Open Graph 与 Twitter Card 的标题、描述、图片和可见页面定位一致。

### 结构化数据

保留并调整现有 JSON-LD：

- `WebSite`：betaer 公开项目与域名资产主页。
- `Person`：betaer 作者实体和 GitHub 主页。
- `CollectionPage`：根页面，包含项目列表与域名列表。
- 项目 `ItemList`：两个 `SoftwareApplication`。
- 域名 `ItemList`：现有域名名称和含义，不添加虚构的 `Offer`、价格或可售状态。
- `BreadcrumbList`：根页面。

两个 `SoftwareApplication` 继续声明真实版本、分类、免费属性、图片和项目 URL。页面可见文案、JSON-LD、OG 文案与标题不得互相矛盾。

### 抓取文件

- `robots.txt` 继续允许根页面与子项目抓取。
- `sitemap.xml` 保留根页面和两个工具页面；不为不存在的域名详情页创建 URL。

## 技术实现

继续使用仓库现有结构：

- `index.html`：完整语义 HTML、CSS、JSON-LD 与少量现有统计脚本。
- `assets/social-preview.svg`：更新可编辑 OG 源图。
- `assets/social-preview.png`：由 SVG 导出为 1200 x 630 PNG。
- `tests/seo.test.mjs`：验证元数据、Schema、项目链接、域名区和联系区。
- `README.md`：只在页面定位变化影响仓库说明时同步调整。

不增加包管理器、前端框架、图标库或构建系统。装饰图形优先使用 CSS；必要图标只使用简单的可访问文本或现有图形资产。

## 交互与失败处理

- 页内锚点在禁用 JavaScript 时仍可工作。
- 外部项目和 GitHub 链接使用明确的目标与安全属性。
- 如果统计脚本加载失败，页面内容、导航和链接仍保持可用。
- 页面不依赖远程字体、远程图片或运行时数据，因此不存在内容加载态和空状态。
- 无效或未核验的域名不自动跳转，避免产生不可控的外部导航失败。

## 响应式与可访问性

- 语义结构使用 `header`、`nav`、`main`、`section`、`footer`。
- 每个主要分区有可定位标题和稳定锚点。
- 移动端在 768px 以下切换为单列；域名列表按可读宽度自动收缩。
- 正文和按钮满足 WCAG AA 对比度。
- 焦点顺序与页面视觉顺序一致。
- 所有外部链接名称能够独立表达目标，不只显示“点击这里”。

## 验证

自动验证：

- 运行现有 Node 测试。
- 新增根页面 HTML 与 SEO 断言，覆盖标题、description、canonical、OG、Twitter Card 和 JSON-LD。
- 断言项目区包含两个正确项目 URL。
- 断言域名区包含现有全部域名，且不再使用中文句号表示域名分隔符。
- 断言结构化数据分别包含项目 `ItemList` 和域名 `ItemList`。

人工验证：

- 在桌面和移动视口检查首屏、项目区、域名区和联系区。
- 检查键盘导航、焦点状态和链接目标。
- 检查浅色与深色系统偏好下页面仍保持一致且可读；页面本身维持统一浅色主题。
- 运行 Lighthouse，重点检查 SEO、Accessibility、Best Practices 与 CLS。
- 使用 Schema Markup Validator 检查 JSON-LD 语法与实体引用。

## 非目标

- 不创建 `/domains/` 路由或独立域名站点。
- 不增加账号、表单提交、询价系统、后台或数据库。
- 不增加 Changelog、博客或多页面内容系统。
- 不把主页包装成大型 Security Lab 品牌站。
- 不为域名虚构报价、访问量、注册年限或可售状态。
